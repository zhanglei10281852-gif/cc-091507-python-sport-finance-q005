# 领域说明

康复疗程会跨越预授权、保单年度和多个支付方，治疗、收据和赔付时间可能不一致。每次补件、更正和拒赔都应保留原始证据链。免赔额、责任比例、票据版本和补件期限是账本的核心信息。

`reference/domain.json` 保存公开的治疗项目、索赔状态、支付方类型、单据类型和事件类型。正式记录使用稳定标识，并区分服务时间（`service_date`）、接收时间（`received_at`）和影像版本（`images[].version`）。

## 关键设计

- **支付方顺序**：系统按保单 `priority` 决定（商业保险 10 → 俱乐部福利 20 → 个人账户兜底），前台提交理赔时不指定支付方，杜绝手工填错顺序导致的重复申请。
- **费用拆分**：每条费用行在各支付方间流转，四类归属（可报 / 待补件 / 个人承担 / 已拒赔）之和恒等于费用总额。责任依据（比例、免赔额、预授权、方案版本）随每个归属片段保存在 `portion.basis`。
- **决定时点**：预授权过期（`preauth_expired`）、治疗方案变更（`plan_changed`）、跨年度保单切换（`policy_year_switch`）、跟进标记（`follow_up_flagged`）都写入事件流，`at` 为决定时点；处方的每次变更也带 `decided_at`。
- **票据版本**：收据影像只追加新版本（`original` / `supplement`），供应商补传不覆盖原始影像；同一球员 + 供应商 + 票号的重复登记幂等返回原收据。
- **重复索赔**：同一收据的理赔提交幂等，返回原申请及当前状态。
- **累计器**：免赔额与年度额度按球员 + 保单年度累计（可跨疗程）；补件导致重算时，该理赔的累计影响整体回滚后重算。
- **补件期限**：待补件理赔自提交起算（默认 30 天），期限到达自动标记 `follow_up` 并写事件；补件后重算拆分并解除标记。
